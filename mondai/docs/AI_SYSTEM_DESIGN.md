# AI システム設計（AI_SYSTEM_DESIGN）

## 構成
```
ブラウザ（js/ai/client.js）
  │  Supabase のログイン中セッション（JWT）を付けて POST
  ▼
Supabase Edge Function `ai`（supabase/functions/ai/index.ts）
  ├─ JWT 検証・ワークスペース権限確認・利用上限チェック
  ├─ プロバイダー抽象化（providers/anthropic.ts、他は同じインターフェースで追加）
  ├─ 作業ごとのプロンプト（prompts.ts）と JSON スキーマ検証
  └─ ai_jobs に履歴（モデル・トークン数・結果）を記録
```
- API キーは Edge Function の秘密情報 `ANTHROPIC_API_KEY` にのみ置く。ブラウザ・リポジトリには置かない。
- 使用モデルは秘密情報 `AI_MODEL`（既定 `claude-opus-5-5`）で切り替え。
- 未設定（Supabase 未接続・未ログイン・キー未設定）のときは AI 画面に理由と設定手順を表示し、ほかの機能は通常どおり動く。

## 作業（action）
| action | 入力 | 出力 |
| --- | --- | --- |
| `parse_request` | 自然文の依頼 | 構造化条件（教科・学年・単元・難易度・数・形式・時間・配点・除外・解説の詳しさ） |
| `generate` | 構造化条件＋既存問題の要約（重複回避） | 問題配列（共通問題形式。計算問題は `check` 式つき） |
| `solve` | 問題（正答を伏せる） | 独立に解いた答え |
| `explain` | 問題＋正答 | 詳細解説・初学者向け・発展・別解・よくある誤答・採点基準 |
| `review` | 問題 | 校閲結果（明確性・選択肢の妥当性・範囲適合・学年適合・難易度）と修正案 |
| `plan_material` | 教材の目的 | 教材構成案（ブロック案） |
| `suggest_review` | 学習結果の集計 | 復習教材の提案 |

## 品質検証パイプライン（AI の自己評価だけに頼らない）
1. **形式検証**（クライアント）：必須項目・選択肢数・正解番号の範囲・数式記法。
2. **独立解答**：別の呼び出し（`solve`、正答を伏せる）で解き、正答と照合。不一致は `needs_fix`。
3. **機械検算**：`check` 式がある問題は `mathcheck.js` で評価し、正答と一致するか確認。
4. **校閲**：`review` で明確性・範囲・学年・難易度・選択肢を点検。
5. **重複**：`similarity.js` で既存問題との類似を検出し候補を提示。
6. 状態：`unverified → verifying → verified`（1〜5 を通過）／`needs_fix`。**人間が確認して「承認」するまで問題バンクの正式データにならない**（`approved` のみ通常検索に出る。AI 生成の未承認は「承認待ち」一覧に出る）。

## 既存問題の優先利用
問題生成の前に問題バンクを条件検索し、足りる場合は既存問題を選定。不足分だけ生成する。結果画面では「既存」「新規（AI）」をラベルで区別する。

## 利用量管理
`ai_jobs` にトークン数を記録。秘密情報 `AI_DAILY_TOKEN_LIMIT`（ユーザーごと、既定 200,000）を超えると拒否。設定画面に当日・当月の使用量を表示。
