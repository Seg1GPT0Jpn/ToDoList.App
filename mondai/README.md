# 教材制作プラットフォーム

問題バンク・教材制作・テスト制作・解答解説・AI・チーム・分析をそなえた、ブラウザで動く教材づくりのアプリです。インストール不要で、開くだけで使えます。

**公開ページ：https://seg1gpt0jpn.github.io/ToDoList.App/mondai/**

## できること
| 画面 | できること |
| --- | --- |
| ホーム | はじめての案内・サンプル作成、作業中の教材、承認待ち・要修正・レビュー待ち、最近の教材と操作 |
| 問題バンク | 問題の登録・編集・削除・複製、一括編集・削除・承認、JSON / CSV の入出力、検索式（AND・OR・除外・項目指定）、単元の複数選択、類似・重複の検出、変更履歴と旧版への復元、★評価 |
| AIスタジオ | 依頼文から条件を読み取り、問題バンクを先に探して足りない分だけ AI が作成。検算・独立解答・校閲・重複確認で検証し、**人が承認するまで正式な問題にしない** |
| 教材制作 | 18 種類のテンプレート（入試3形式を含む）、見出し・文章・大問・問題・表・**図形（作図）**・画像・解答欄・改ページ、**数値替え版**、ドラッグで並べかえ、元に戻す・やり直し、自動保存、版の保存、用紙（A4/B4/A3/B5・縦横）・余白・2段・文字サイズ・ヘッダー・フッター・ページ番号、単語・用語テスト |
| テスト制作 | 範囲・満点・時間・問題数・大問・難易度と形式の割合・除外タグから自動で出題、配点を満点に合わせて自動配分（一致を確認）、A・B・C 版（B版以降は数値も変えられる）、**神奈川県公立高校入試・共通テスト・二次試験の形式** |
| 解答・解説 | 正答・解説・別解・採点基準・誤答の確認と編集、問題が更新されたときの「要再確認」、解答用紙・解答解説集だけの印刷 |
| ライブラリ | 教材の検索・フォルダ・タグ・複製・アーカイブ・取り込み・書き出し |
| チーム | ログイン、チーム作成・招待・権限（オーナー／管理者／編集者／レビュアー／閲覧者）、教材と問題の共有、レビュー（承認・差し戻し）、コメント、公開、活動履歴 ※クラウド設定が必要 |
| 分析 | 結果の記録（表に入力・CSV）、問題別・単元別・難易度別・学習者別の正答率、誤答の傾向、つまずきの多い問題から復習プリント |
| 設定・データ | zip / json の取り込み、保存状況、バックアップ・復元、ダークモード、クラウド接続、AI の状態と使用量、操作履歴・エラー記録 |

最初から **高校5教科・96単元・3,840問のオリジナル問題** が入っています（AI が作成し、別の AI が全問を解き直して確認済み。授業で使う前に先生の確認をおすすめします）。

## 使い方（基本の流れ）
1. **問題バンク**で教科・単元・難易度をしぼり、「＋追加」または「ランダムに追加」
2. **教材制作**で見出しや説明文を足し、「用紙・印刷」で解答欄・配点・大問のまとめ方・用紙を決める
3. 「印刷／PDF」（または「問題用紙」「解答用紙」「解答・解説」）で印刷。PDF にするにはプリンターで「PDF に保存」を選ぶ（ファイル名は【試験名】【問題／問題+解答／問題+解答・解説】になります）

テストを作るなら **テスト制作** で条件を決めて「問題を選ぶ」→「教材として作成」。

## データの保存とバックアップ
- データはこのブラウザの中（IndexedDB）に保存され、ログインしない限りインターネットには送られません。
- ブラウザのデータ消去や端末の故障に備えて、**設定・データ → バックアップを保存** をときどき行ってください。別の端末でも「バックアップから復元」で同じ状態にできます。
- もらった問題データ（zip）は **設定・データ** にドラッグして読み込めます（再配布不可のデータはリポジトリに入れていません）。

## チーム機能と AI を使うには（任意）
Supabase（無料枠）の設定が必要です。手順は [supabase/README.md](supabase/README.md)。
1. Supabase のプロジェクトを作り、`supabase/migrations/0001_init.sql` を SQL Editor で実行
2. メールでのログインを有効にし、Site URL を公開ページの URL にする
3. AI を使う場合は Edge Function `ai` をデプロイし、秘密情報 `ANTHROPIC_API_KEY`（Claude の API キー）を登録（任意で `AI_MODEL` `AI_EFFORT` `AI_DAILY_TOKEN_LIMIT`）
4. アプリの **設定・データ → クラウド接続** に Project URL と anon key を入れる

- anon key は公開してよい鍵です（権限はデータベース側のルールで守られます）。**service_role キーと Claude の API キーは、ブラウザやリポジトリに絶対に入れないでください。**
- 設定しなくても、チームと AI 以外の機能はすべて使えます。
- 現時点で、実際の Supabase・Claude API との接続は確認できていません（データベースの権限ルールはテスト用のデータベースで検証済み）。

## 開発者向け
- 構成：ビルド不要の ES モジュール。`js/core`（保存・移行・バックアップ）、`js/domain`（ロジック）、`js/render`（印刷用 HTML）、`js/ui`（画面）、`js/ai`、`js/cloud`、`supabase/`（SQL・Edge Function）
- 設計資料：[docs/](docs/)（現状調査・全体計画・進捗・機能一覧・システム構成・データベース・AI・画面・移行・テスト）
- 公開：`main` ブランチに入れると GitHub Pages に反映されます（ビルド工程なし）

```bash
cd mondai
npm install
npm test            # 単体テスト＋データベースの権限テスト
npm run typecheck   # 型検査
npm run test:e2e    # ブラウザでの通しテスト
```

既知の問題と今後の拡張候補は [docs/DEVELOPMENT_PROGRESS.md](docs/DEVELOPMENT_PROGRESS.md) にあります。
