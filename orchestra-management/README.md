# かながわコネクトオーケストラ 応募者・団員管理システム（Apps Script v2）

Googleフォームの回答を「応募者一覧」に取り込み、楽器別・パート別の募集状況や活動状況を自動で集計する、スプレッドシート用の Apps Script です。

| ファイル | 内容 |
|---|---|
| `Code.gs` | 本体（既存の Code.gs と置き換え） |
| `Tests.gs` | セルフテスト（任意。メニューから実行。シートは変更しません） |
| `test/` | ローカル検証用（Node.js）。Apps Script には入れません |

---

## 導入手順（既存のスプレッドシートに適用）

> 既存のシート・データ・フォーム・フォームURL・トリガーはそのまま使えます。削除は不要です。

1. **まずスプレッドシートのコピーで試す**（推奨）
   「ファイル → コピーを作成」→ コピー側の「拡張機能 → Apps Script」で 2〜4 を実施。確認後、コピーは削除してください（個人情報を含むため）。
2. Apps Script エディタで既存の `Code.gs` の中身を**すべて**この `Code.gs` に置き換えて保存
   - 旧コードを同じプロジェクト内に別ファイルで残さないでください（関数名が重複してエラーになります）。旧コードはこのリポジトリの `test/fixtures/Code_v1_original.gs` に保存済みです。
   - プロジェクト内に別の `onEdit` 関数がある場合は、どちらか一方にまとめてください。
3. （任意）「＋ → スクリプト」で `Tests.gs` を追加して貼り付け
4. スプレッドシートを再読み込み → メニュー「🎻 オーケストラ管理」
   1. **① 初期セットアップ**（何度実行しても安全。既存の応募者は再登録されません）
   2. **⑩ システム診断** … フォームの質問と列の対応、楽器名の判定結果を確認
   3. **⑧ データ整合性チェック** … 問題が出たら内容に沿って修正
   4. 必要なら「🛠 メンテナンス → 楽器名の表記を統一」（v1 時代の「チューバ」等を `Tuba` に揃える）
5. フォーム送信トリガーは v1 のものがそのまま動きます（**③ の再設定は不要**）。⑤ 接続状況で「重複」と出たときだけ ③ を実行してください。

初回実行時に権限の確認が出た場合は、内容（このスプレッドシートの読み書き・トリガー）を確認して許可してください。Googleフォーム自体を変更する権限は使いません。

## シート構成

| シート | 役割 | 編集 |
|---|---|---|
| フォームの回答 N | Googleフォームの回答（読むだけ） | しない |
| **応募者一覧** | 団員管理の中心データ。A〜U列は v1 と同じ、V列に「同期メモ」を追加 | **する** |
| **連絡記録** | 連絡の履歴。v1 の9列＋「次回対応内容」「対応状況」 | **する** |
| **募集設定**（新規） | 団員目標・判断ライン・最低人数、楽器ごとの目標人数、表記ゆれ | **する** |
| 楽器別集計 | 自動生成（A〜G列は v1 と同じ意味） | しない |
| 活動状況 | 自動生成（1〜9行目は v1 と同じ項目） | しない |
| ダッシュボード（新規） | 全体／募集状況／パート別／活動状況を1画面に | しない |
| データチェック（新規） | ⑧⑨ の結果 | しない |
| システム診断（新規） | ⑩ の結果 | しない |
| _同期履歴（新規・非表示） | 取り込み済み回答のハッシュ（個人情報は含まない） | しない |

※ 同名のシートを運営が別用途で作っていた場合は上書きせず「〜（自動）」という名前で作ります。

| メニュー | 内容 |
|---|---|
| ① 初期セットアップ | シートの準備＋同期＋集計（既存データは消さない） |
| ② 既存回答を同期 | 未登録の回答だけ追加 |
| ③ フォーム送信トリガー設定 | 自動同期トリガーを1本に整理して設定 |
| ④ ダッシュボード更新 | 楽器別集計・活動状況・ダッシュボードを更新 |
| ⑤ 接続状況を確認 | 回答シート・トリガー・未同期件数・最終自動同期 |
| ⑥ 楽器別集計を更新 | ④ ＋ 急募パートを表示 |
| ⑦ 応募者管理を更新 | 列の追加、No. の空欄補完、プルダウン再設定、重複の印、連絡記録の反映 |
| ⑧ データ整合性チェック | 重複・未知の楽器名/ステータス・空欄・不正な日付・同期/集計の不一致 |
| ⑨ 重複チェック | 二重取込・同じメールアドレス・同名 |
| ⑩ システム診断 | 列/質問の対応、トリガー、設定、楽器名の判定結果 |
| 🛠 楽器名の表記を統一 | 応募者一覧の楽器列を `Tuba` 等に揃える（確認あり） |
| 🛠 セルフテスト | Tests.gs のテスト（シートは変更しない） |

## 運用ルール（v2）

- **No.（応募者ID）は一度振ったら変わりません。** 並べ替えても連絡記録の「応募者No.」とずれません。
- **同じ人の再回答は上書きせず新しい行として追加**し、「同期メモ」に `⚠重複候補` と記録します。集計は No. の小さい行（最初の応募）で1人として数えます。不要な行は削除して構いません（**削除した回答は同期で復活しません**）。
- 楽器が判定できない回答（例：サックス）は**推測で割り当てず**、そのまま保存して「未分類」として数えます。「募集設定」の「追加の表記ゆれ」に書けば集計されます。
- 「ヴァイオリン」とだけ回答した人は `Vn`（1st/2nd未定）。振り分けたら楽器列を `1st Vn` / `2nd Vn` に変えてください。
- ピッコロ・バスクラ等は別の楽器として数え、ダッシュボードではパート（Fl・Cl 等）でまとめて表示します。目標人数が必要なら「募集設定」に入力してください。
- 応募者一覧の「対応状況」や「楽器」、連絡記録、募集設定を編集すると集計が自動更新されます（募集設定で「いいえ」にすると停止）。

### 募集状況の判定（人数は「募集設定」で変更）

| 条件（有効応募者数で判定） | 表示 |
|---|---|
| 目標・最低とも未設定 | 目標未設定 |
| 0人（または 最低×急募割合 未満。初期値は0） | 急募 |
| 最低人数 未満 | 募集中（最低未達） |
| 目標人数 未満 | 募集中 |
| 目標×1.5 以上（倍率は変更可） | 充足／調整 |
| それ以外 | 充足 |

有効応募者＝「集計から除外するステータス」（初期値：辞退）以外の応募者。

## v1 からの変更点まとめ

### 見つかった問題（v1 のコードで再現を確認：`test/audit-original.js`）

| # | 問題 | v2 での対応 |
|---|---|---|
| 1 | 「チューバ」「ヴァイオリン」「ピッコロ」等が正規化されず、楽器別集計で0人扱い | 表記ゆれ吸収（全角半角・長音・ヴ/ブ・括弧・複数回答）。集計時にも正規化するので、v1 で取り込まれた行も正しく数える |
| 2 | 活動状況 B9 の判定式が1行ずれ（60人で「最低人数到達」、80人で「判断ライン到達」） | 正しい判定に修正（＋「団員目標達成」） |
| 3 | 応募者数がメールアドレス列の件数（メール空欄は数えない） | 実人数（重複除く）で数える |
| 4 | ① 再実行で楽器別集計を全消去し、運営が変えた目標人数が消える | 目標は「募集設定」に保存。移行時に v1 シートの値を引き継ぐ |
| 5 | No. を毎回行番号で振り直す → 並べ替えると連絡記録と別人になる | No. は固定。空欄の行だけ採番 |
| 6 | 手動で削除した応募者が次の同期で復活する | _同期履歴（ハッシュ）で取込済みを記録 |
| 7 | ロックが無く同時実行で二重登録の恐れ | LockService で排他 |
| 8 | 質問名が1つ変わると手動同期は全停止、自動同期は黙って空欄で取り込む | 見出しの表記ゆれ・前方一致で列を探し、見つからない項目は確認ダイアログ＋同期メモに記録 |
| 9 | ダイアログ付き関数がトリガー文脈で落ちる | 画面が無いときはログに残すだけ |
| 10 | 「=」で始まる自由記述が数式として実行される（IMPORTXML 等で外部送信の恐れ） | 文字列として保存 |
| 11 | 列位置（H列・R列など）を固定で参照 | 見出し名で列を探す（列の挿入・並び替えに強い） |
| 12 | フォーム再リンクで「フォームの回答 2」ができると古いシートを読む | 連携中のシートを優先し、全回答シートを重複なく処理。別フォームの回答シートは対象外 |
| 13 | appendRow を1件ずつ実行（人数に比例して遅くなる） | 一括書き込み（150人でも書き込み16回） |
| 14 | v1 のフィルタが A〜U列のみ → 追加列があると並べ替えで行がずれる | フィルタ範囲をデータ全体に拡張（絞り込み条件は保持） |

### 変えていないもの

- 既存のシート・データ・フォーム・フォームURL・トリガー（関数名 `handleSpreadsheetFormSubmit` も同じ）
- 応募者一覧の A〜U 列の並びと見出し、対応状況7種類の名前と順番（団員アプリ連携で、末尾に「活動休止」を追加）、第1回演奏会・連絡方法の選択肢
- 重複判定キー「回答日時＋メールアドレス」、楽器コード（Fl, Ob, …, Cb）と v1 の目標・最低人数
- メニュー①〜⑤の名前と順番、`CONFIG` の既存の値

### 個人情報の扱い

- 集計・ダッシュボード・データチェック・システム診断・ログには**名前とメールアドレスを出しません**（No. のみ）。
- _同期履歴には「回答日時＋メール」の SHA-256 ハッシュのみ保存（メールアドレス自体は複製しない）。
- 連絡記録の「氏名」補完は v1 からある列を空欄の場合だけ埋めます。
- ダッシュボード等を外部に公開する場合は、このスプレッドシートを共有せず、集計値だけを別のスプレッドシートにコピーしてください。

## 団員アプリとの連携（AppSync.gs）

応募者一覧で対応状況が「**正式参加**」の人を、団員アプリ（Firebase プロジェクト `kanagawa-connect-official`）へ同期します。アプリ側の詳細は `../kco-member-app/README.md` を参照してください。

| ファイル | 内容 |
|---|---|
| `AppSync.gs` | 同期処理（Apps Script に「AppSync」として追加） |
| `AppNotify.gs` | プッシュ通知の送信（Apps Script に「AppNotify」として追加） |
| `appsscript.json` | Firestore に書き込む権限（datastore）と、通知を送る権限（firebase.messaging）を含むマニフェスト |
| `test/appsync-tests.js` | 同期・通知のテスト（偽の Firestore・偽の通知サービスを使用） |

- メニュー：「🎻 オーケストラ管理」→「📱 団員アプリ」
  - 同期の内容を確認（お試し）／団員アプリへ同期／自動同期を設定（15分ごと）／アプリ連携設定を開く
  - プッシュ通知をいますぐ送信／通知の送信を設定（10分ごと）
- 初めて同期すると、応募者一覧の末尾に「**アプリID**」（団員ごとに固定）と「**アプリ用メールアドレス**」（任意。ログインに別のアドレスを使う場合）の列が追加されます。
- 送るのは、メールアドレス（ログイン許可用）・表示名・楽器・パートと、集計値だけです。
- 正式参加でなくなった人は削除せず「利用停止」にします。一度に半数以上が利用停止になる変更は、自動では反映しません。
- 対応状況が「**活動休止**」の人は団員のまま「閲覧のみ」になります（団員数に含め、休止中の人数も表示）。「正式参加」に戻すと元どおり使えます。
  - プルダウンに「活動休止」を出すには、「⑦ 応募者管理を更新」を1回実行してください。

### プッシュ通知（AppNotify.gs）

- 団員アプリで運営が「送信を予約」した通知と、練習の前日通知（「明日は練習です」）を、通知をオンにした団員の端末に送ります。
- 「アプリ連携設定」の「プッシュ通知の送信」を「はい」にし、メニュー「通知の送信を設定（10分ごと）」を1回実行すると始まります。
- 前日通知は、公開中で日付が決まっている練習だけ、設定した時刻（初期値 18時）以降に1回だけ送ります。
- 送り先は在籍中・活動休止中の団員と運営の端末だけです。退団した人には送りません。届かなくなった端末の登録は自動で削除します。
- 送る前に「送信中」にするため、二重には送りません（途中で止まった通知は再送せず「失敗」と記録）。
- 秘密鍵・サーバーキーは使いません（実行者の Google アカウントの権限で送信）。ログにメールアドレス・通知トークンは出しません。
- 送るものが無いときは、通知の予約だけを確認します（端末や団員の一覧は読まないので、Firestore の読み取り回数が増えません）。
- 秘密鍵は使いません。実行した Google アカウント（Firebase プロジェクトのオーナー）の権限で書き込みます。

```bash
TZ=Asia/Tokyo node test/appsync-tests.js   # 団員アプリ同期のテスト
```
