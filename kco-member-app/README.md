# かながわコネクトオーケストラ 団員専用アプリ

加入が確定した団員だけが使える Web アプリ（PWA）です。スマートフォンのホーム画面に追加して使えます。

- 練習予定と出欠
- お知らせ（プッシュ通知つき）
- 演奏会情報
- 団員一覧・パート編成・団員数
- **楽譜**（自分のパートの楽譜だけ見られる）
- **みんなで**：アンケート、団員からの提案（賛成・運営からの返信）
- **団員募集のシェア**：募集カード（画像）を作って、インスタ・LINE などで送れる

運営は同じアプリの「運営」画面から、予定・お知らせ・演奏会・アンケート・楽譜・通知・募集キャンペーンを登録します。
募集カードの QR コードは、誰でも見られる**募集ページ**（`/join`）につながります。

> **「団員を管理するためだけのアプリ」ではなく、「団員みんなでオーケストラをつくっていくためのアプリ」** を目指しています。

## 全体の仕組み

```
［一般公開］公式サイト（既存プロジェクト kanagawa-connect-orchestra・変更なし）

［運営専用］Googleフォーム → スプレッドシート（応募者一覧・個人情報）
                     │ Apps Script「📱 団員アプリへ同期」（AppSync.gs）
                     │  ・対応状況＝正式参加 の人だけ
                     │  ・送るのは メール（ログイン許可用）・表示名・楽器・パート のみ
                     │ Apps Script「プッシュ通知の送信」（AppNotify.gs・10分ごと）
                     ▼
［団員専用］団員アプリ（Firebase プロジェクト kanagawa-connect-official）
            Authentication ／ Firestore ／ Hosting ／ Cloud Messaging ／（任意）Storage
            └ 募集ページ /join だけは一般公開（募集の内容のみ。個人情報なし）
```

- **参加希望者と加入確定者は別管理**です。アプリを使えるのは、スプレッドシートで対応状況が「正式参加」の人だけです。
- 権限は、アプリの画面ではなく **Firestore セキュリティルール（サーバー側）で強制**しています。
- 公式サイトとは別の Firebase プロジェクトにしているため、互いのルールや公開作業が影響し合いません。

## 使用している技術

| 部分 | 技術 |
|---|---|
| アプリ | TypeScript ＋ React 19 ＋ Vite 8（PWA） |
| ログイン | Firebase Authentication（メールリンク／Google） |
| データ | Cloud Firestore ＋ Security Rules |
| 公開 | Firebase Hosting |
| 同期・通知の送信 | Google Apps Script → Firestore REST API／FCM HTTP v1 API（実行者の Google 権限を使い、秘密鍵は使わない） |
| 楽譜ファイル | Cloud Storage for Firebase（任意。使わない場合は Google ドライブ等のリンクで配布） |
| 募集カード | ブラウザ内の Canvas で画像を作成（外部サービスに送らない）＋ QR コード（qrcode） |
| テスト | Vitest ／ Firebase エミュレータ ／ @firebase/rules-unit-testing ／ Playwright |

## データ構造（Firestore）

| コレクション | 内容 | 読める人 | 書ける人 |
|---|---|---|---|
| `memberAccess/{メール}` | 状態（active / paused / inactive）・権限（member / staff / admin）・団員ID・パート | 本人・管理者 | **同期のみ**（アプリからは誰も不可） |
| `members/{団員ID}` | 表示名・楽器・パート・自己紹介・役職表示 | 団員 | 本人：表示名・自己紹介のみ／管理者：表示名・自己紹介・役職表示のみ |
| `stats/summary` | 団員数・目標・パート別人数 | 団員 | 同期のみ |
| `adminStats/summary` | 参加希望者数・対応状況別人数 | 管理者 | 同期のみ |
| `rehearsals/{id}` | 練習予定（未定の項目は空欄） | 団員（公開中のもの） | 運営補助・管理者 |
| `rehearsals/{id}/attendance/{団員ID}` | 出欠（出席・遅刻・欠席。回答がなければ未回答） | 本人・運営 | 本人（締切まで） |
| `announcements/{id}` | お知らせ（重要フラグ・種類・対象） | 団員（公開中のもの） | 運営補助・管理者 |
| `concerts/{id}` | 演奏会情報（日時・会場は未定なら空欄） | 団員（公開中のもの） | 管理者 |
| `surveys/{id}` | アンケート（質問・締切・匿名・公開した集計結果） | 団員（公開中のもの） | 運営補助・管理者 |
| `surveys/{id}/responses/{団員ID}` | 回答（1人1件、受付中は修正可） | 本人・運営 | 本人（受付中のみ・在籍中のみ） |
| `proposals/{id}` | 団員からの提案（公開範囲：団員みんな／運営だけ）・対応状況・運営の返信・賛成数 | 「団員みんな」は団員、「運営だけ」は本人と運営 | 投稿：本人（自分の表示名のみ）／内容の修正：本人（受付中のみ）／対応状況・返信：運営 |
| `proposals/{id}/supports/{団員ID}` | 賛成（1人1回。賛成数と同時にだけ増減できる） | 本人 | 本人 |
| `scores/{id}` | 楽譜（対象パート、ファイルまたはリンク） | 対象パートの団員・運営 | 運営補助・管理者 |
| `pushTokens/{トークン}` | 通知を受け取る端末 | 本人のみ | 本人のみ（Apps Script が読んで送信） |
| `notifications/{id}` | 通知の送信予約と結果 | 運営 | 予約：運営／結果：Apps Script のみ |
| `appConfig/public` | ウェブプッシュの公開鍵（秘密情報ではない） | 団員 | 管理者 |
| `publicCampaign/current` | 団員募集の内容（見出し・メッセージ・募集パート・応募フォームURL など） | **だれでも**（募集ページ） | 運営補助・管理者（項目はルールで固定） |

Cloud Storage（任意）：`scores/{楽譜ID}/{ファイル}` … 対象パートの団員と運営だけが取得でき、運営だけが PDF・PNG・JPEG（30MB まで）を置けます。

メールアドレス・本名・年代・地域・所属などの個人情報は、`members` には置きません。他の団員から見えるのは、表示名・楽器・パート・自己紹介・役職表示だけです。

## 権限

| ユーザー | できること |
|---|---|
| 未ログイン | ログイン画面と、団員募集ページ（`/join`）のみ |
| 参加希望者・未登録 | 「加入確定後にご利用いただけます」画面のみ |
| 退団・辞退（inactive） | 「現在ご利用いただけません」画面のみ |
| 活動休止（paused） | 閲覧のみ（楽譜・お知らせは見られる。出欠・アンケート回答・提案・プロフィール変更は不可）。通知は受け取れる |
| 団員（member） | 閲覧、自分の出欠、アンケートへの回答、提案・賛成、自分のパートの楽譜、募集カードのシェア、通知のオン・オフ、自分の表示名・自己紹介の変更 |
| 運営補助（staff） | 上記に加えて、練習予定・お知らせ・アンケート・楽譜・通知・募集キャンペーンの作成、全員の出欠と回答の確認、提案への返信 |
| 管理者（admin） | 上記に加えて、演奏会情報、参加希望者数、表示名・役職表示の修正、通知の公開鍵の設定、アンケート・提案の削除 |

権限の付与・変更は、スプレッドシートの「アプリ連携設定」シートで行います。アプリからは変更できません（なりすまし・誤操作防止のため）。

## 状態の区分

### ✅ 使える状態
- ログイン（メールリンク・Google）、ログアウト、ログイン状態の保持、状態ごとの画面の出し分け
- ホーム：団員数（例：4 / 80人、活動休止中の人数）、重要なお知らせ、次回練習と自分の出欠、演奏会、楽譜・アンケート・提案・団員一覧への入口、最新のお知らせ、パート編成
- 練習予定（これから・日程未定・過去）、出欠の登録・変更（締切あり）、ひとことコメント
- お知らせ（重要表示、種類、対象：全員・セクション・パート、自分向けの絞り込み、保存時にプッシュ通知）
- 演奏会情報（未定の項目は「未定」と表示）
- 団員一覧（パート別、表示名・楽器のみ）、マイページ（表示名・自己紹介・通知のオン／オフ）
- **アンケート**：1つ選ぶ／いくつでも／自由記述、必須、締切、匿名、回答の修正、集計（横棒グラフ）、集計結果の団員への公開（自由記述は公開しない）、回答した人・まだの人（匿名でないときだけ）
- **団員からの提案**：投稿（団員みんなに公開／運営だけに送る）、賛成（1人1回）、運営の対応状況（受付・検討中・採用・実現・見送り）と返信
- **楽譜**：対象パートを指定して配布（リンク／ファイル）。対象外のパートの団員には、一覧にもファイルにもアクセスできない（ルールで制限）
- **プッシュ通知**：運営が送る通知、お知らせ・アンケート・楽譜の保存時の通知、練習の前日通知（自動）、送信履歴、届かなくなった端末の自動削除
- **団員募集キャンペーン**：募集ページ（一般公開）、募集カード（投稿用 4:5／ストーリーズ用 9:16、QR コードつき）、画像のシェア（インスタ・LINE など）、画像の保存、LINE・X で送る、文章のコピー、募集パートを人数から自動で選ぶ
- **活動休止**：スプレッドシートの対応状況「活動休止」→ アプリは閲覧のみ
- 運営画面：概要、練習・出欠、お知らせ、演奏会、アンケート、楽譜、通知、募集、団員
- スプレッドシート → アプリの同期（お試しモード、手動同期、15分ごとの自動同期）

### 🟡 仮の実装・簡易版
- お知らせの「対象」は表示の絞り込み用です。他パート向けのお知らせも「すべて表示」で見られるため、秘密の連絡には使えません（楽譜の対象パートは本当に制限されます）。
- 匿名アンケートは「運営の画面に名前を出さない」方式です。データ上は団員IDと結びついているため、Firebase の管理者がデータベースを直接見れば分かります（アプリの画面では分かりません）。
- 通知は Apps Script が10分ごとに送るため、予約から届くまで最大10分ほどかかります。
- 募集カードの団員数は、募集キャンペーンを保存した時点の人数です（人数が変わったら保存し直してください）。
- 楽譜を「リンク」で配布する場合、リンク先（Google ドライブなど）の共有設定によっては団員以外も開けます。
- アイコンは仮のデザイン（KC の文字）です。正式なロゴ画像に差し替えられます。

### ⬜ まだ作っていないもの
- 練習のパート別対象指定、出欠の CSV 出力
- アンケート結果の CSV 出力
- Android／iOS アプリ化（Capacitor）

### ⚙️ 本番で追加の設定が必要なもの（下の手順 5）
- 更新版の公開（`npm run deploy`）と Apps Script のファイル更新・再承認
- 通知：ウェブプッシュ証明書（公開鍵）の登録、Apps Script の「通知の送信を設定」
- 楽譜ファイルのアップロードを使う場合：Blaze プランへの変更と Storage の有効化（リンクで配布するなら不要）
- 募集キャンペーン：応募フォームの URL などの入力

## 本番公開の手順

### 1. Firebase コンソールでの設定（初回のみ・約10分）

[Firebase コンソール](https://console.firebase.google.com/) で `kanagawa-connect-official` を開きます。

1. **Firestore を作る**：「構築」→「Firestore Database」→「データベースを作成」
   - ロケーション：`asia-northeast1（東京）`
   - モード：「本番環境モード」
2. **ログイン方法を有効にする**：「構築」→「Authentication」→「始める」→「Sign-in method」
   - 「メール / パスワード」を有効にし、**「メールリンク（パスワードなしでログイン）」もオン**にする
   - 「Google」を有効にする（サポートメールには運営のアドレスを選ぶ）
   - 「設定」→「ユーザー アクション」で「メール列挙保護」がオンになっていることを確認する
3. **Web アプリを登録する**：⚙️「プロジェクトの設定」→「全般」→「マイアプリ」→「</>（ウェブ）」
   - アプリ名は `kco-member-app` など
   - 「Firebase Hosting も設定する」にチェック
   - 表示される設定値は**コピー不要**です（Hosting が自動で配信します）
4. 「Authentication」→「設定」→「承認済みドメイン」に `kanagawa-connect-official.web.app` があることを確認する

### 2. アプリを公開する（ブラウザだけで完結：Google Cloud Shell）

1. [Google Cloud Shell](https://shell.cloud.google.com/) を開きます（Firebase と同じ Google アカウントで）。
2. 次のコマンドを1行ずつ貼り付けて実行します。

```bash
git clone https://github.com/Seg1GPT0Jpn/ToDoList.App.git
cd ToDoList.App && git checkout claude/vigilant-knuth-nret0u && cd kco-member-app
npm ci
npx firebase login --no-localhost        # 表示されるURLを開いて許可し、コードを貼り付け
npm run deploy                            # ビルド → ルールとアプリを公開
```

3. 公開先：`https://kanagawa-connect-official.web.app`

更新するときは、`git pull` のあとに `npm run deploy` を実行します。

### 3. スプレッドシートと連携する（Apps Script）

応募者管理のスプレッドシートで「拡張機能」→「Apps Script」を開きます。

1. **Code.gs を最新版に置き換える**（`orchestra-management/Code.gs`。メニューと新しい列に対応しています）
2. 「＋」→「スクリプト」で **`AppSync`** を作り、`orchestra-management/AppSync.gs` の中身を貼り付ける
3. ⚙️「プロジェクトの設定」→「『appsscript.json』マニフェスト ファイルをエディタで表示する」にチェックし、`appsscript.json` を `orchestra-management/appsscript.json` の内容に置き換える
   - Firestore に書き込む権限（datastore）を追加するためです。保存後の初回実行時に、権限の承認画面が出ます
4. スプレッドシートを再読み込み → 「🎻 オーケストラ管理」→「📱 団員アプリ」→「**アプリ連携設定を開く**」
   - 「Firebase プロジェクトID」が `kanagawa-connect-official` になっていることを確認する
   - 「管理者のメールアドレス」に、実行した人（kzmsegawa@gmail.com）が自動で入ります
5. 「📱 団員アプリ」→「**同期の内容を確認（お試し・書き込みなし）**」で、内容を確認する
6. 問題なければ「**団員アプリへ同期**」を実行する
7. （任意）「アプリ連携設定」の「自動同期」を「はい」にして、「**自動同期を設定（15分ごと）**」を実行する

> 同期は、実行した Google アカウントの権限で Firestore に書き込みます。そのため、**Firebase プロジェクトのオーナー（または編集者）のアカウントで実行**してください。秘密鍵や API キーは使いません。

### うまくいかないとき（実際に起きたこと）

| 表示 | 原因と対処 |
|---|---|
| `Cannot call SpreadsheetApp.getUi() from this context`（onOpen） | Apps Script のエディタで onOpen を実行したため。エラーではないので、スプレッドシートを再読み込みすればメニューが出ます |
| `UrlFetchApp.fetch を呼び出す権限がありません` | スプレッドシートを開いているアカウントが、まだ権限を許可していません。ブラウザで複数アカウントにログインしている場合は、メニューが**ふだん使うアカウント**で動きます。そのアカウントで、エディタから `appSyncPreview` を一度実行して許可してください |
| `Firebase に書き込む権限がありません（403）` | 実行しているアカウントが Firebase プロジェクトのメンバーではありません。Firebase コンソール →「ユーザーと権限」で、そのアカウントをオーナー（または編集者）として追加し、招待を承認してください |
| `firebase login` で `Unable to authenticate` | 認証コードを貼る前に Enter を押したため。Cloud Shell では `npx firebase logout` のあと、ログインせずに `npm run deploy` でも公開できます |

### 4. 団員への案内（例）

> 団員専用ページを公開しました。`https://kanagawa-connect-official.web.app` を開き、参加希望フォームで登録したメールアドレスを入力すると、ログイン用のリンクが届きます。スマートフォンでは「ホーム画面に追加」するとアプリのように使えます。

学校のメールアドレスなどでリンクが届かない場合は、応募者一覧の「アプリ用メールアドレス」列に別のアドレスを入力し、同期してください。

### 5. 追加機能の設定（アンケート・提案・楽譜・通知・団員募集・活動休止）

#### 5-1. アプリを更新する（Cloud Shell）

```bash
cd ~/ToDoList.App && git pull && cd kco-member-app
npm ci
npm run deploy        # ルール・インデックス・アプリを公開
```

`ToDoList.App` フォルダが無い場合は、手順 2 の `git clone` からやり直してください。公開後、新しいインデックスの作成に数分かかることがあります（その間はアンケート・提案・楽譜の一覧が「読み込みに失敗しました」になる場合があります）。

#### 5-2. Apps Script を更新する

1. `Code.gs`・`AppSync.gs` を最新版に置き換える
2. 「＋」→「スクリプト」で **`AppNotify`** を作り、`orchestra-management/AppNotify.gs` を貼り付ける
3. `appsscript.json` を最新版に置き換える（通知を送る権限 `firebase.messaging` が増えています）
4. **スプレッドシートの持ち主のアカウント**で、エディタから `appSyncPreview` を1回実行し、権限を承認し直す
5. スプレッドシートを再読み込み →「📱 団員アプリ」→「**団員アプリへ同期**」を1回実行
   - ログイン許可に「パート」が追加されます（楽譜の閲覧範囲に使います）。**この同期をするまで、団員には全員向けの楽譜しか表示されません**
6. 「🎻 オーケストラ管理」→「⑦ 応募者管理を更新」を1回実行（対応状況のプルダウンに「**活動休止**」が追加されます）

#### 5-3. プッシュ通知を使う

1. Firebase コンソール → ⚙️「プロジェクトの設定」→「Cloud Messaging」→「ウェブプッシュ証明書」→「**鍵ペアを生成**」
2. 表示された長い文字列（公開鍵）をコピーし、アプリの「運営」→「通知」→「通知の設定」に貼り付けて保存
3. スプレッドシートの「アプリ連携設定」で「**プッシュ通知の送信**」を「はい」にする（前日通知の有無・時刻もここで変えられます）
4. 「📱 団員アプリ」→「**通知の送信を設定（10分ごと）**」を1回実行
5. 団員は「マイページ」→「この端末で通知を受け取る」をオンにします
   - **iPhone・iPad** は、Safari の共有ボタン →「ホーム画面に追加」をして、ホーム画面のアイコンから開いたときだけ通知を受け取れます（iOS 16.4 以降）

#### 5-4. 楽譜を配布する

- **リンクで配布（設定不要）**：Google ドライブなどの共有リンクを「運営」→「楽譜」で登録します。ドライブの共有は「リンクを知っている全員」ではなく、団員だけに限定するのがおすすめです。
- **ファイルをアップロード（任意）**：Firebase の Storage が必要です。Storage は **Blaze プラン（従量課金）** でのみ使えます（無料枠内なら料金はかかりません。念のため予算アラートを設定してください）。
  1. Firebase コンソール →「アップグレード」→ Blaze を選び、予算アラート（例：100円）を設定
  2. 「構築」→「Storage」→「始める」→ ロケーション `asia-northeast1`・本番環境モード
  3. Cloud Shell で：
     ```bash
     cd ~/ToDoList.App/kco-member-app
     npm run deploy:storage       # 「Firestore を参照する権限を付与しますか？」と聞かれたら y
     npm run setup:storage-cors   # アプリから楽譜を直接開けるようにする（バケット名が違う場合は package.json を修正）
     ```

#### 5-5. 団員募集キャンペーン

1. アプリの「運営」→「募集」で、見出し・メッセージ・応募フォームの URL・ハッシュタグを入力
2. 「人数から自動で選ぶ」で、目標人数に届いていないパートを選ぶ（手で調整も可能）
3. 「募集中にする」をオンにして保存
4. 団員はホームまたは「みんなで」→「団員募集をシェア」で、カード画像をインスタ・LINE に送れます
   - 募集ページ：`https://kanagawa-connect-official.web.app/join`（ログイン不要。カードの QR コードの行き先）

#### 追加機能でうまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 楽譜が「配布中の楽譜はまだありません」 | 5-2 の 5（同期）をまだ実行していないため、団員のパートが登録されていません。同期を1回実行してください |
| 通知が「送信待ち」のまま | 「プッシュ通知の送信」が「いいえ」、またはトリガー未設定です。5-3 の 3・4 を確認してください。「📱 団員アプリ」→「プッシュ通知をいますぐ送信」でも送れます |
| 通知が「失敗：通知を送る権限がありません」 | `appsscript.json` の更新後に権限を承認し直していないか、実行アカウントが Firebase プロジェクトのオーナーではありません（5-2 の 3・4） |
| マイページに「通知機能は準備中です」 | 5-3 の 1・2（公開鍵の登録）がまだです |
| ファイルのアップロードで「Storage の有効化が必要です」 | 5-4 の Storage 設定がまだです。リンクで配布することもできます |

## セキュリティについて

- ソースコードに秘密情報はありません。Firebase の設定値は、本番では Hosting の `/__/firebase/init.json` から読み込みます。`.env` は Git の管理対象外です。
- ログイン許可・権限（`memberAccess`）は同期だけが書き込みます。アプリからは、管理者を含め誰も変更できません。
- 本人が変更できるのは、表示名と自己紹介だけです（楽器・状態・権限は変更不可）。
- 入力値の長さ・形式・項目名もルールで検査しています（余計な項目の追加を拒否）。
- 出欠は、本人のものだけ締切まで登録できます。他人の出欠は運営だけが見られます。
- ルールに書いていないコレクションは、すべて拒否します。Storage は楽譜のフォルダ以外を全面拒否します。
- 楽譜は、Firestore と Storage の両方のルールで「対象パートの団員だけ」に制限しています（画面の表示だけの制限ではありません）。
- 提案の投稿者名は、本人の団員プロフィールの表示名と一致する場合だけ保存できます（なりすまし防止）。賛成は1人1回で、数だけを増やすことはできません。
- 通知の送信は Apps Script（運営の Google アカウントの権限）だけが行います。アプリから他人の端末へ直接通知を送ることはできません。通知の宛先トークンは本人しか読めません。
- 団員募集ページ（`/join`）で公開されるのは `publicCampaign/current` だけで、保存できる項目をルールで固定しています（メールアドレス等は保存できません）。
- 募集カードの画像はブラウザの中だけで作るため、外部の画像サービスに情報を送りません。
- Hosting で、セキュリティ関連のヘッダー（nosniff・フレーム埋め込み禁止など）を設定しています。検索エンジンにも登録されません（noindex）。
