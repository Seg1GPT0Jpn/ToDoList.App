# かながわコネクトオーケストラ 団員専用アプリ（Phase 1）

加入が確定した団員だけが使える Web アプリ（PWA）です。スマートフォンのホーム画面に追加して使えます。

- 練習予定と出欠
- お知らせ
- 演奏会情報
- 団員一覧・パート編成
- 団員数

これらを1か所で確認できます。運営は同じアプリの「運営」画面から、予定・お知らせ・演奏会情報を登録します。

> **「団員を管理するためだけのアプリ」ではなく、「団員みんなでオーケストラをつくっていくためのアプリ」** を目指します。Phase 1 では土台（ログイン・権限・情報共有・出欠）をつくり、アンケートや団員からの提案は Phase 3 で追加します。

---

## 全体の仕組み

```
［一般公開］公式サイト（既存プロジェクト kanagawa-connect-orchestra・変更なし）

［運営専用］Googleフォーム → スプレッドシート（応募者一覧・個人情報）
                     │ Apps Script「📱 団員アプリへ同期」（AppSync.gs）
                     │  ・対応状況＝正式参加 の人だけ
                     │  ・送るのは メール（ログイン許可用）・表示名・楽器・パート のみ
                     ▼
［団員専用］団員アプリ（Firebase プロジェクト kanagawa-connect-official）
            Authentication ／ Firestore ／ Hosting
```

- **参加希望者と加入確定者は別管理**です。アプリを使えるのは、スプレッドシートで対応状況が「正式参加」の人だけです。
- 権限は、アプリの画面ではなく **Firestore セキュリティルール（サーバー側）で強制**しています。
- 公式サイトとは別の Firebase プロジェクトにしているため、互いのルールや公開作業が影響し合いません。

## 使用している技術

| 部分 | 技術 |
|---|---|
| アプリ | TypeScript ＋ React 19 ＋ Vite 8（PWA） |
| ログイン | Firebase Authentication（メールリンク／Google） |
| データ | Cloud Firestore ＋ Security Rules |
| 公開 | Firebase Hosting |
| 同期 | Google Apps Script → Firestore REST API（実行者の Google 権限を使い、秘密鍵は使わない） |
| テスト | Vitest ／ Firebase エミュレータ ／ @firebase/rules-unit-testing ／ Playwright |

## データ構造（Firestore）

| コレクション | 内容 | 読める人 | 書ける人 |
|---|---|---|---|
| `memberAccess/{メール}` | 状態（active / paused / inactive）・権限（member / staff / admin）・団員ID | 本人・管理者 | **同期のみ**（アプリからは誰も不可） |
| `members/{団員ID}` | 表示名・楽器・パート・自己紹介・役職表示 | 団員 | 本人：表示名・自己紹介のみ／管理者：表示名・自己紹介・役職表示のみ |
| `stats/summary` | 団員数・目標・パート別人数 | 団員 | 同期のみ |
| `adminStats/summary` | 参加希望者数・対応状況別人数 | 管理者 | 同期のみ |
| `rehearsals/{id}` | 練習予定（未定の項目は空欄） | 団員（公開中のもの） | 運営補助・管理者 |
| `rehearsals/{id}/attendance/{団員ID}` | 出欠（出席・遅刻・欠席。回答がなければ未回答） | 本人・運営 | 本人（締切まで） |
| `announcements/{id}` | お知らせ（重要フラグ・種類・対象） | 団員（公開中のもの） | 運営補助・管理者 |
| `concerts/{id}` | 演奏会情報（日時・会場は未定なら空欄） | 団員（公開中のもの） | 管理者 |

メールアドレス・本名・年代・地域・所属などの個人情報は、`members` には置きません。他の団員から見えるのは、表示名・楽器・パート・自己紹介・役職表示だけです。

## 権限

| ユーザー | できること |
|---|---|
| 未ログイン | ログイン画面のみ |
| 参加希望者・未登録 | 「加入確定後にご利用いただけます」画面のみ |
| 退団・辞退（inactive） | 「現在ご利用いただけません」画面のみ |
| 活動休止（paused） | 閲覧のみ（出欠・プロフィール変更は不可） |
| 団員（member） | 閲覧、自分の出欠、自分の表示名・自己紹介の変更 |
| 運営補助（staff） | 上記に加えて、練習予定・お知らせの作成、全員の出欠確認 |
| 管理者（admin） | 上記に加えて、演奏会情報、参加希望者数、表示名・役職表示の修正 |

権限の付与・変更は、スプレッドシートの「アプリ連携設定」シートで行います。アプリからは変更できません（なりすまし・誤操作防止のため）。

## 状態の区分

### ✅ 使える状態（Phase 1）
- ログイン（メールリンク・Google）、ログアウト、ログイン状態の保持、状態ごとの画面の出し分け
- ホーム：団員数（例：4 / 80人）、重要なお知らせ、次回練習と自分の出欠、演奏会、最新のお知らせ、パート編成
- 練習予定（これから・日程未定・過去）、出欠の登録・変更（締切あり）、ひとことコメント
- お知らせ（重要表示、種類、対象：全員・セクション・パート、自分向けの絞り込み）
- 演奏会情報（未定の項目は「未定」と表示）
- 団員一覧（パート別、表示名・楽器のみ）、マイページ（表示名・自己紹介）
- 運営画面：概要（参加希望者数と加入確定者数を分けて表示、パート別の不足）、練習予定の登録・下書き、出欠の集計（全体・パート別・未回答者）、お知らせ、演奏会、団員一覧（役職表示）
- スプレッドシート → アプリの同期（お試しモード、手動同期、15分ごとの自動同期）

### 🟡 仮の実装・簡易版
- お知らせの「対象」は表示の絞り込み用です。他パート向けのお知らせも「すべて表示」で見られるため、秘密の連絡には使えません。
- アイコンは仮のデザイン（KC の文字）です。正式なロゴ画像に差し替えられます。
- 活動休止（paused）には、アプリ側では対応済みです。ただしスプレッドシートの対応状況に「活動休止」はまだありません（現在は正式参加以外はすべて利用停止になります）。

### ⬜ まだ作っていないもの（次の Phase）
- アンケート・団員からの提案（Phase 3）
- 楽譜の配布（Phase 4、Cloud Storage を使用。現在は Storage を全面的に拒否する設定）
- プッシュ通知（「明日は練習です」など）
- 練習のパート別対象指定、出欠の CSV 出力
- Android／iOS アプリ化（Capacitor）

### ⚙️ 本番で追加の設定が必要なもの（下の手順）
- Firebase コンソールでの設定（ログイン方法・Firestore・Web アプリの登録）
- アプリの公開（Hosting）とルールの反映
- Apps Script への AppSync.gs の追加と権限設定

## 本番公開の手順

### 1. Firebase コンソールでの設定（初回のみ・約10分）

[Firebase コンソール](https://console.firebase.google.com/) で `kanagawa-connect-official` を開きます。

1. **Firestore を作る**：「構築」→「Firestore Database」→「データベースを作成」
   - ロケーション：`asia-northeast1（東京）`
   - モード：「本番環境モード」
2. **ログイン方法を有効にする**：「構築」→「Authentication」→「始める」→「Sign-in method」
   - 「メール / パスワード」を有効にし、**「メールリンク（パスワードなしでログイン）」もオン**にする
   - 「Google」を有効にする（サポートメールには運営のアドレスを選ぶ）
   - 「設定」→「ユーザー アクション」で「メール列挙保護」がオンになっていることを確認する
3. **Web アプリを登録する**：⚙️「プロジェクトの設定」→「全般」→「マイアプリ」→「</>（ウェブ）」
   - アプリ名は `kco-member-app` など
   - 「Firebase Hosting も設定する」にチェック
   - 表示される設定値は**コピー不要**です（Hosting が自動で配信します）
4. 「Authentication」→「設定」→「承認済みドメイン」に `kanagawa-connect-official.web.app` があることを確認する

### 2. アプリを公開する（ブラウザだけで完結：Google Cloud Shell）

1. [Google Cloud Shell](https://shell.cloud.google.com/) を開きます（Firebase と同じ Google アカウントで）。
2. 次のコマンドを1行ずつ貼り付けて実行します。

```bash
git clone https://github.com/Seg1GPT0Jpn/ToDoList.App.git
cd ToDoList.App && git checkout claude/vigilant-knuth-nret0u && cd kco-member-app
npm ci
npx firebase login --no-localhost        # 表示されるURLを開いて許可し、コードを貼り付け
npm run deploy                            # ビルド → ルールとアプリを公開
```

3. 公開先：`https://kanagawa-connect-official.web.app`

更新するときは、`git pull` のあとに `npm run deploy` を実行します。

### 3. スプレッドシートと連携する（Apps Script）

応募者管理のスプレッドシートで「拡張機能」→「Apps Script」を開きます。

1. **Code.gs を最新版に置き換える**（`orchestra-management/Code.gs`。メニューと新しい列に対応しています）
2. 「＋」→「スクリプト」で **`AppSync`** を作り、`orchestra-management/AppSync.gs` の中身を貼り付ける
3. ⚙️「プロジェクトの設定」→「『appsscript.json』マニフェスト ファイルをエディタで表示する」にチェックし、`appsscript.json` を `orchestra-management/appsscript.json` の内容に置き換える
   - Firestore に書き込む権限（datastore）を追加するためです。保存後の初回実行時に、権限の承認画面が出ます
4. スプレッドシートを再読み込み → 「🎻 オーケストラ管理」→「📱 団員アプリ」→「**アプリ連携設定を開く**」
   - 「Firebase プロジェクトID」が `kanagawa-connect-official` になっていることを確認する
   - 「管理者のメールアドレス」に、実行した人（kzmsegawa@gmail.com）が自動で入ります
5. 「📱 団員アプリ」→「**同期の内容を確認（お試し・書き込みなし）**」で、内容を確認する
6. 問題なければ「**団員アプリへ同期**」を実行する
7. （任意）「アプリ連携設定」の「自動同期」を「はい」にして、「**自動同期を設定（15分ごと）**」を実行する

> 同期は、実行した Google アカウントの権限で Firestore に書き込みます。そのため、**Firebase プロジェクトのオーナー（または編集者）のアカウントで実行**してください。秘密鍵や API キーは使いません。

### うまくいかないとき（実際に起きたこと）

| 表示 | 原因と対処 |
|---|---|
| `Cannot call SpreadsheetApp.getUi() from this context`（onOpen） | Apps Script のエディタで onOpen を実行したため。エラーではないので、スプレッドシートを再読み込みすればメニューが出ます |
| `UrlFetchApp.fetch を呼び出す権限がありません` | スプレッドシートを開いているアカウントが、まだ権限を許可していません。ブラウザで複数アカウントにログインしている場合は、メニューが**ふだん使うアカウント**で動きます。そのアカウントで、エディタから `appSyncPreview` を一度実行して許可してください |
| `Firebase に書き込む権限がありません（403）` | 実行しているアカウントが Firebase プロジェクトのメンバーではありません。Firebase コンソール →「ユーザーと権限」で、そのアカウントをオーナー（または編集者）として追加し、招待を承認してください |
| `firebase login` で `Unable to authenticate` | 認証コードを貼る前に Enter を押したため。Cloud Shell では `npx firebase logout` のあと、ログインせずに `npm run deploy` でも公開できます |

### 4. 団員への案内（例）

> 団員専用ページを公開しました。`https://kanagawa-connect-official.web.app` を開き、参加希望フォームで登録したメールアドレスを入力すると、ログイン用のリンクが届きます。スマートフォンでは「ホーム画面に追加」するとアプリのように使えます。

学校のメールアドレスなどでリンクが届かない場合は、応募者一覧の「アプリ用メールアドレス」列に別のアドレスを入力し、同期してください。

## 開発・テスト

```bash
npm ci
npm run test          # 単体テスト（日付・出欠集計・パート）
npm run test:rules    # セキュリティルールの権限テスト（エミュレータ。Java が必要）
npm run typecheck     # 型チェック
npm run build         # 本番用ビルド
npm run dev:emulator  # エミュレータに接続して画面を確認
npm run test:e2e      # ブラウザでの動作確認（エミュレータ＋Chromium。CHROMIUM_PATH で指定可）
```

エミュレータのプロジェクトは `demo-kco` です（実在しない `demo-` プロジェクトのため、本番には接続しません）。

## セキュリティについて

- ソースコードに秘密情報はありません。Firebase の設定値は、本番では Hosting の `/__/firebase/init.json` から読み込みます。`.env` は Git の管理対象外です。
- ログイン許可・権限（`memberAccess`）は同期だけが書き込みます。アプリからは、管理者を含め誰も変更できません。
- 本人が変更できるのは、表示名と自己紹介だけです（楽器・状態・権限は変更不可）。
- 入力値の長さ・形式・項目名もルールで検査しています（余計な項目の追加を拒否）。
- 出欠は、本人のものだけ締切まで登録できます。他人の出欠は運営だけが見られます。
- ルールに書いていないコレクションは、すべて拒否します。Storage も全面拒否です。
- Hosting で、セキュリティ関連のヘッダー（nosniff・フレーム埋め込み禁止など）を設定しています。検索エンジンにも登録されません（noindex）。
