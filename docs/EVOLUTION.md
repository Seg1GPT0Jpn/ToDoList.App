# つづりクエスト 進化計画（PHASE 0：現状分析と設計）

「問題を解くアプリ」から「勉強そのものが冒険になる学習RPG」へ進化させるための設計書です。
既存の資産（問題データ約5,800問・6ワールド・文房具モンスター・フィールド・カード）を生かし、壊さずに段階的に積み上げます。

---

## ① 現状分析

### 構成

| 層 | 場所 | 技術 | 役割 |
| --- | --- | --- | --- |
| コア | `rpg_game/` | 純 Dart | バトル計算・成長・問題データ・学習モード・購入。Flutter/Firebase に依存しない |
| アプリ | `rpg_game_app/` | Flutter 3 + Flame | 画面・フィールド（Flame）・敵の描画（CustomPainter）・保存（SharedPreferences / Firestore） |
| データ | `rpg_game/assets/questions/<world>/*.json` | JSON | 問題セット（1エリア＝1ファイル）。`origin` で著作権ガード |

### ゲームループ（現在）

ワールドマップ → フィールド（Flame、歩いて敵に接触）→ バトル（4択・制限時間・カード）→ 結果（EXP・レベルアップ・カード）→ 次のエリア解放

- 寄り道：宿（授業＋練習）・宝箱（難問）・泉（バフ）・亡霊（間違えた問題と再戦）・仲間の救出
- 学習モード：定期テストの海（全単元が高難度バトル）・試験対策ワールド・単語帳・LEAP（個人用）

### データ構造

- `QuizQuestion`：id / category / prompt / sentence / choices(4) / answerIndex / explanation / passage
- `StageDef`：id / worldId / order / branch / enemy / questionSetIds / 時間・推奨レベル・報酬カード
- `EnemyDef`：name / look / color / maxHp / attack / weakness / armor / セリフ
- `RpgProgress`：レベル・EXP・クリア・記録・購入・デッキ・亡霊（間違えた問題 ID）・宝箱・仲間・海の自己ベスト

### できていること

- 6教科・約5,800問（すべて自作）、教科→ルート→エリアの構造（`RouteWorldBuilder`）
- 弱点・装甲・チェイン・クリティカル・カード・ボス
- 24種の敵の見た目（文房具17＋旧来7）、となりのエリアで同じ見た目にならないテスト
- Google ログイン＋Firestore 同期、プロモーションコード、Web 公開

## ② 問題点一覧

| # | 問題 | 影響 |
| --- | --- | --- |
| P1 | **問題ごとの学習記録がない**（覚えているのは「間違えた問題 ID」だけ） | 苦手の再出題・復習・成長の可視化ができない |
| P2 | 出題が完全ランダム | 苦手な問題が自然に再登場しない。得意な問題ばかり出ることもある |
| P3 | 成長がレベルだけ | 「何ができるようになったか」が見えない。教科ごとの到達度がない |
| P4 | **音が一切ない** | 気持ちよさ・没入感・ボスの特別感が大きく欠ける |
| P5 | 図鑑・実績・クエストがない | 収集・目標・毎日続ける理由がない |
| P6 | ホーム（ワールドマップ）が「次に何をすればいいか」を示さない | 迷う。遊ぶ理由を自分で作る必要がある |
| P7 | ボス登場の演出が通常の敵と同じ | ボスが特別に見えない |
| P8 | 設定画面がない（文字サイズ・音・アニメーション軽減） | アクセシビリティ不足 |
| P9 | 敵データが「見た目の名前」だけで、カテゴリ・レア度・性格・図鑑説明がない | 図鑑やコレクションの土台がない |
| P10 | 問題データにヒント・タグ・難易度・よくある間違いを持てない | 多角的な出題・丁寧な解説に広げにくい |
| P11 | 教科ごとの色・音・モチーフが画面によってばらばら | 「その教科の世界に来た」感じが弱い |
| 技術的負債 | `battle_screen.dart`（1,400行）・`field_game.dart`（1,000行）が大きい。進行状況が1つのドキュメントに集中 | 今後の拡張で衝突しやすい |

## ③ 改善優先順位

学習効果とゲームの手ごたえの両方に効くものから順に進めます。

1. **学習記録（P1・P2）**：すべての土台。苦手の再登場、復習、成長の見える化はここから生まれる
2. **成長の見える化（P3）**：教科レベル・習得問題数・連続学習日数
3. **音（P4）**：BGM と SE。「学習が進むほど曲が完成する」演出で、学習の成果を耳で感じられるようにする
4. **ホームの情報設計（P6）**：次の目標・今日のクエスト・連続学習日数
5. **図鑑・実績・称号・クエスト（P5・P9）**
6. **ボス演出（P7）**・設定（P8）・問題スキーマ拡張（P10）・教科デザイン（P11）
7. 大きなファイルの分割、マップの視覚化（世界地図）、NPC、スキル、新しい敵の追加（後述のロードマップ）

## ④ 新アーキテクチャ案

```
rpg_game/lib/src/
├─ learning/          ← 新設：学習記録と適応出題
│  ├─ question_stat.dart     1問ごとの記録（回答数・正解数・連続・最終回答日・平均時間・復習の箱）
│  ├─ learning_record.dart   全体の記録（圧縮して保存）・学習日・教科別集計
│  ├─ review_planner.dart    復習する問題を選ぶ（間違い・遅い・久しぶり・期限切れ）
│  └─ adaptive.dart          出題の重みづけ（苦手ほど早く出る）・おすすめエリア
├─ meta/              ← 新設：遊びの外側の仕組み
│  ├─ enemy_species.dart     敵の種族データ（カテゴリ・サイズ・レア度・性格・図鑑説明・固有SE）
│  ├─ journal.dart           図鑑・実績・クエスト・称号の記録
│  ├─ achievements.dart      実績と称号の定義（条件はデータ＋関数）
│  └─ quests.dart            デイリークエストの生成（日付から決まる・学習目標と結びつける）
rpg_game_app/lib/
├─ audio/             ← 新設：BGM・SE・学習連動の音楽レイヤー
├─ settings/          ← 新設：文字サイズ・音・アニメーション軽減
├─ collection/        ← 新設：図鑑・実績・称号
└─ app/design.dart    ← 新設：教科ごとの色・アイコン・音楽・モチーフ（デザイントークン）
```

方針：

- **コアは純 Dart のまま**。記録・復習・実績の判定はすべてコアでテストする
- **保存は分ける**：進行状況（`rpg_progress`）とは別に、学習記録（`rpg_learning`）と図鑑・実績（`rpg_journal`）を保存する。問題数が増えても1つのドキュメントが肥大しない
- 既存の画面は大きく書き換えず、フック（バトルの `onTurn` など）で新しい仕組みをつなぐ

## ⑤ ゲームシステム案

### 学習と強さの循環

```
探索 → 敵・イベント → 問題 → 記録（得意・苦手）→ 成長（教科レベル・習得数）→ 新エリア・実績・称号 → 探索
```

- **苦手が自然に再登場**：バトルの出題は「苦手度」「復習の期限」で重みをつける（完全ランダムではない）。同じ問題が連続しないように、既存の山札のしくみは残す
- **復習の塔（新）**：間違えた・時間がかかった・久しぶり・期限が来た問題を集めて戦う。間隔反復（ライトナー方式：正解で箱が上がり、次に出るまでの日数が 1→2→4→8→16→32 日と伸びる）
- **教科レベル**：その教科で「習得した問題数」から決まる。勉強した量ではなく、できるようになった量が強さになる
- **おすすめエリア**：定期テストの海で、まだ習得率の低い最初のエリアに「次はここ」を表示（勝手に難易度を変えず、提案するだけ）
- **デイリークエスト**：日付から3つ決まる。例「数学Ⅰの2次関数で3問連続正解」「復習の塔で10問正解」「ボスを1体倒す」。達成で EXP
- **実績・称号**：初勝利、ボス討伐、連続学習日数、苦手克服（2回以上まちがえた問題を3回連続正解）など。称号はホームに表示
- **図鑑**：出会った敵はシルエットから名前つきに、倒すと図鑑説明が読める。種族ごとのレア度で枠が変わる

### 難易度（内部 4 段階）

`basic / standard / advanced / challenge`。数学のエリア名（基本・標準・応用）から自動で決まり、問題データにも `difficulty` を持てる。challenge は隠しステージ・ボス用に予約する。

## ⑥ データ構造案

問題（既存の JSON に、任意のフィールドを追加。書いていない問題もそのまま読める）：

```json
{
  "id": "mat_m101_011", "category": "calculation",
  "prompt": "...", "choices": ["...", "...", "...", "..."], "answerIndex": 0,
  "explanation": "...",
  "difficulty": "standard",
  "hint": "平方完成してみよう",
  "tags": ["2次関数", "最大・最小"],
  "commonMistakes": ["軸が定義域の外にあることを見落とす"]
}
```

教科・ルート・エリアは、既存の `worldId / branch / setId` から決まるので、問題に重複して書かない（数万問に増えても整合性が崩れない）。

1問ごとの記録（`QuestionStat`、保存は配列で圧縮）：
`attempts / correct / streak / missStreak / lastDay / totalMs / box / dueDay / setId`

図鑑・実績（`PlayerJournal`）：
`seen{enemyId:回数} / defeated{…} / achievements{id:日付} / title / quest{日付, 進み具合, 受け取り済み} / bossKills`

## ⑦ UI/UX 改善案

- **ホーム**：上から「プレイヤー（レベル・称号・連続学習日数）」→「次の目標」→「今日のクエスト」→「定期テストの海・復習の塔」→「ワールド（教科ごとの色・習得率つき）」→「図鑑・実績・設定」
- **3つの問い**に常に答える：どこにいるか（教科色＋ルート名）／次に何をするか（次の目標カード）／どれだけ伸びたか（教科レベル・習得数）
- **設定**：文字サイズ（標準・大・特大）、BGM・SE の ON/OFF、アニメーション軽減。色だけで情報を伝えない（アイコン・文字も添える）
- 教科ごとのデザイントークン（色・アイコン・モチーフ・音楽）を `app/design.dart` にまとめ、画面ごとのばらつきをなくす

## ⑧ 敵・ボス設計案

- 24種の見た目を **種族** として定義：カテゴリ（筆記具系・紙ノート系・計測製図系・整理加工系・学校用品系・古典魔物系）、サイズ（小・中・大・ボス）、レア度（COMMON〜LEGENDARY）、性格、攻撃のしかた、図鑑説明、固有 SE
- 教科との結びつき：数学＝計測・製図系（定規・分度器・コンパス）、国語＝紙・ノート系（本・ページ・付箋）、社会＝古典魔物系（ゴーレム・ナイト・ドラゴン）など、種族カテゴリと出現教科の対応を図鑑に表示
- **ボス演出**：画面が暗くなる → 「BOSS」の帯と名前 → 専用 SE → ボス専用 BGM（全パートが最初から鳴る）
- 今後：情報の国向けに「キーボード・マウス・ケーブル」系の新種族、ボス専用の大型描画（ロードマップ）

## ⑨ BGM・SE 設計案

すべてコードで合成して MP3 にする（外部素材・著作権の心配がない。同じ合成器で作るので音の世界観がそろう）。

| 曲 | 用途 | 性格 |
| --- | --- | --- |
| home | ホーム | 明るいピアノ＋やわらかいパッド |
| field_japanese | 国語の探索 | ピアノと弦、温かい |
| field_math | 数学の探索 | 電子的なアルペジオ、規則的 |
| field_english | 英語の探索 | 軽快なプラック、明るい |
| field_science | 理科の探索 | 透明なベル＋空間的なパッド |
| field_social | 社会の探索 | 五音音階の旋律＋低音の太鼓 |
| field_information | 情報の探索 | シンセのビート |
| battle（4パート） | 通常バトル | ピアノ／ベース／打楽器／ストリングス |
| boss（4パート） | ボス戦 | 短調・速いテンポ、全パートが最初から鳴る |
| victory・defeat・levelup | ジングル | 短い |

**学習で曲が完成する**：通常バトルは最初ピアノだけ。正解でベース、3連続正解で打楽器、5連続でストリングスが加わる。まちがえるとパートが1つ減る。正解を重ねるほど曲が完成していくので、学習の手ごたえが音で分かる。

SE：決定・キャンセル・正解・不正解・攻撃・クリティカル・被ダメージ・回復・レベルアップ・宝箱・ステージクリア・ボス登場・ボス撃破・ページめくり・実績解除。
